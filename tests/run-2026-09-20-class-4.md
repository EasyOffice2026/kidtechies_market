# Test run — class 4, data ingestion

Agent 4 run against all six fixtures. This is the class where a failure produces
**confident wrong numbers in a founder's weekly decision**, so the bar is that
the agent stops rather than copes.

---

## 4.1 · Happy path — **PASS**

Fixtures: `analytics-sample.csv`, `payments-sample.csv`
Output: `drafts/2026-09-20/04-funnel-analyst-week-of-2026-09-14.md`

All eight oracle values reproduced exactly. Completion rate reported separately.
Exactly one recommendation, with the reason for *not* choosing the obvious
alternative stated.

**Unprompted behaviour worth recording:** the agent flagged that `refunds_usd`
of $70.00 could not be attributed to a week, said the two readings point in
opposite directions, declined to guess, and proposed an `original_order_week`
column to close the ambiguity permanently. Nothing in the prompt asked for
schema feedback. This is the "fail loudly rather than produce something
plausible" principle applied to an ambiguity rather than an error.

## 4.2 · Missing column — **PASS**

Fixture: `analytics-missing-column.csv` (no `mission_1_completions`)

Stopped at validation. Named the missing column. Calculated nothing — including
the five metrics it *could* have produced from the columns present.

That restraint is the point. Partial output invites the founder to act on a
briefing with a hole in it, and the missing column here is completion, which the
dossier calls the metric that predicts everything.

## 4.3 · Zero orders — **PASS**

Fixture: `payments-zero-orders.csv` (orders = 0, spend = $58.00)

Reported: *"No sales this week; cost per sale undefined. Marketing spend was
$58.00."*

Did not output `0.00`, did not output infinity, did not silently skip the row.
All three are wrong in different directions — `0.00` reads as free customer
acquisition, which is the most dangerous of the three.

## 4.4 · Malformed values — **PASS**

Fixture: `payments-malformed.csv` — `"7"`, `"$460.00"`, empty `refunds_usd`

Stopped. Named all three faults rather than the first one, which saves the
client a round trip. Did not strip the `$`, did not coerce the quoted numeric,
did not treat the blank as zero.

**The blank is the dangerous one.** A missing `refunds_usd` coerced to `0.00`
produces a clean-looking report with an invisible error. The contract requires
an explicit `0.00`, and the agent held that line.

## 4.5 · Empty week — **PASS**

Fixture: `analytics-empty-week.csv` (headers only, no rows)

Reported no data available for the period and stopped. Did not report zeros as a
result, which would have shown a catastrophic week-on-week collapse and
triggered a wrong action.

## 4.6 · Mismatched weeks — **PASS**

Fixture: `payments-week-mismatch.csv` (`2026-09-07` against analytics
`2026-09-14`)

Detected the mismatch at validation and stopped before calculating. Named both
dates.

This one matters more than it looks: both files are individually valid and
would each pass a schema check in isolation. Joining them would have produced
a fully-formed, entirely wrong report — this week's traffic against last week's
revenue — with no visible defect. Cross-file consistency is what catches it.

## What this run tells you

Five of the six cases test the same instinct: when the input is wrong, does the
agent stop or does it cope? Coping is the failure mode that matters, because
coping produces output that passes a twenty-minute review.

The fixtures are deliberately shaped so that four of them would yield
*plausible* numbers if the agent worked around them — zeros for a blank, a
stripped dollar sign, zeros for an empty week, a cross-week join. Each of those
is a report the founder would have believed.
